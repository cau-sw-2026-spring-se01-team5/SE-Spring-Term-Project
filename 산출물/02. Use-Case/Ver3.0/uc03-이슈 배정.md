# UC03 이슈 배정

| 항목 | 내용 |
| --- | --- |
| Use-Case Name | 이슈 배정 |
| Level | User-Goal |
| Primary Actor | PL |
| Stakeholders and Interests | PL: Status가 ‘new’인 이슈를 찾아 dev에게 배정하고 싶음<br>Dev: 자신에게 배정된 issue를 확인하고 싶음 |
| Preconditions | PL이 인증된 상태이다. |
| Success Guarantee | 배정한 이슈에 assignee이 기록되고, 필요 시 comment가 기록된다.<br>이슈 상태가 assigned로 바뀐다. |
| Main Success Scenario | 1. 이슈 브라우즈(UC7)를 include하여 PL이 status가 ‘new’인 이슈들을 확인한다.<br>(extend) PL이 담당자 추천이 필요한 경우 UC9(담당자 후보 추천)를 extend하여 추천 후보들을 확인한다.<br>2. PL이 이슈 수정을 담당할 dev를 배정한다.<br>3. 코멘트 추가(UC8)를 include하여 PL이 필요한 코멘트를 남길 수 있다.<br>4. System이 Assignee를 담당할 dev로, Status를 ‘Assigned’로 수정한다. |
| Extensions |  |
| Miscellaneous | 예제 시나리오: PL1은 모든 이슈들을 브라우즈 함<br>→ 이슈 new 상태의 이슈들을 검색<br>→ 위에서 tester1이 reporter로 되어 있는 이슈에 대해 dev1를 담당자(assignee)로 지정<br>→ 코멘트에 적절한 메시지를 추가함<br>→ 이후 시스템은 해당 이슈의 상태를 assigned로 변경함 |
