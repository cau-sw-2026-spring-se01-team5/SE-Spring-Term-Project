1. 프로젝트 방향성
해당 이슈관리 시스템은 개발 팀의 진행 상황과 작업 이슈(버그 수정)을 일관된 프로세스로 등록, 업무 할당, 추적이 가능하도록 돕는다.

역할별(Admin/PL/Dev/tester) Role을 다르게 설정해 팀원별로 맡은 업무를 수행할 수 있도록 지원
이슈 등록, dev 배정, 수정 사항 기재 등 기능을 구현해 발생한 이슈 관리를 가능하도록 함
assignee 값, 이슈 status 등으로 원하는 필터를 설정해 브라우즈하도록 함
검색된 이슈들의 통계 분석 기능을 제공함

1-1. 기능 방향성
- 이슈 관리에 필요한 필수적인 기능(등록, 상태 변경)을 우선적으로 완성
- 검색과 통계 분석을 통해 데이터 기반 의사결정을 지원
- 이전에 해결되었던 이슈의 이력들을 기반으로 assignee을 추천할 수 있는 기능 추가. 여러 가지 방법으로 테스트를 시도해 가장 정확도가 높은 방법 적용

1-2. 설계 방향성
- MVC 패턴을 적용하여 UI와 Applications logic을 분리
- Swing, JavaFX 총 2개의 UIToolKit으로 구현


1-3. 품질 방향성
- SQLite에 데이터를 저장해 시스템을 재시작하여도 일관성을 보장하도록 구현
- unit 테스트가 가능하도록 시스템을 설계하고 JUnit 테스트 코드 작성

2. Stakeholders
1. Admin: 프로젝트 및 계정(역할) 관리
2. PL: 이슈 브라우즈 후 dev에게 배정, 수정된 이슈 종료 처리
3. Dev: 배정 받은 이슈를 브라우즈 후 해결, 수정 사항 기록
4. tester: 이슈 등록 후 자신이 reporter인 이슈가 수정되었는지 확인
5. 경영진(Offstage): 처리량, 이슈 발생 빈도 등 결과 지표 확인

3. High-Level Requirements

3-1. 기능 요구사항
1. Role 기반으로 계정 등록(Admin/PL/Dev/tester)
2. 이슈 브라우즈 (Status, Reporter name)
3. 이슈 등록 (Title, Description는 필수적으로 입력. 이슈를 등록한 아이디로 reporter를, 등록한 날짜와 시간으로 reported date를 자동으로 채움)
4. 이슈 코멘트 추가
5. 이슈 상세 정보 확인 (이슈의 각 필드와 코멘트 history 확인 가능)
6. 이슈 배정을 포함한 이슈 상태 변경
7. 이슈 통계 분석(일/월 별 이슈 발생 횟수 및 트랜드 등 표시)
8. 해결된(closed/resolved) 이슈 이력을 활용한 assignee 자동 추천 기능


3-2. 비기능 요구사항
1. 영속성: 시스템을 재시작하여도 데이터 유지
2. 확장성: 저장소, UI 교체가 용이해야 함
3. 테스트 용이성
4. 사용성
